# 契約6（つなぐ側 ↔ OctantCompass）: 見つけ方と接続

> 固さ: 後から記録する層（[憲法の原則 10](../constitution.md#10-段階と文書の固さ)）。公開（リリース）の前は実装が先で、この文書を後から合わせます。

版 2.0 · 境界: つなぐ側（OctantPath の MOD、OctantPath Desktop など）↔ OctantCompass · 実装する側: OctantPath と OctantCompass · 形の正本: この文書と [mod-api.openapi.yaml](mod-api.openapi.yaml)

つなぐ側と OctantCompass は、通信だけでつながります。互いのファイルを読まず、つなぐ側は OctantCompass を起動しません。同じ PC でも別の端末（別の PC、Android の Beat Saber など）でも手順は同じで、同じ PC はつなぐ先が 127.0.0.1 なだけの場合です（2026-10-13 決定）。

利用者が入れるのは、Beat Saber の DLL（MOD）や OctantPath Desktop と、OctantCompass だけです。つなぐ側どうしも別物として扱い、ファイルを共有しません。MOD と OctantPath Desktop は、それぞれ別にペアリングし、別のトークンを持ちます（2026-10-13）。

## 見つける

| 項目 | 案 |
| --- | --- |
| 既定のポート | OctantCompass は既定で 23287 番のポートで待ち受ける（2026-10-13 決定）。設定で変えてよい |
| 同じ PC | つなぐ側は、自分の設定につなぐ先がなければ、まず `127.0.0.1` の既定のポートの `/v1/health` を試す |
| 別の端末 | 当面、LAN での自動の発見は持たない（2026-10-13 決定: Quest などのために今から方式を決めるのは早い）。別の端末からは、つなぐ側に OctantCompass のアドレスとポートを手で入れる |
| 手で入れる | つなぐ側はアドレスとポートを手で入れられる（ポートを省いたら既定のポート）。OctantCompass は自分の画面に、つなぐ先のアドレスとポートを出す |
| 覚える | つなぐ側は、つないだアドレスとポート、トークンを自分の設定に持つ。アドレスが変わったら、利用者が入れ直す |

## ペアリング

| 項目 | 案 |
| --- | --- |
| 合言葉 | OctantCompass が画面に短い合言葉を出す（6 桁の数字、有効な時間 300 秒、失敗 5 回で無効、1 回使ったら無効。数値は OctantCompass の設定）。利用者がそれをつなぐ側に 1 回入れ、つなぐ側は `POST /v1/pair` を呼んでトークンを受け取る。同じ PC でも同じ手順で、人の操作なしにペアリングする道は持たない |
| トークン | つなぐ側は受け取ったトークンを自分の設定に持ち、OctantCompass で取り消すまで使い続ける。401 を受けたら、合言葉を入れ直すよう表示する |
| 通信の保護 | 当面は LAN でも平文の HTTP（2026-10-13 決定: 多くの VR 機器も平文）。同じネットワークからトークンと合言葉が読めることは受け入れる |

## 起動と常駐

つなぐ側は OctantCompass を起動しません。OctantCompass が見つからなければ、推薦機能だけを止めて「OctantCompass が見つからない」と表示し、ゲームは通常どおり動かします。

OctantCompass をいつ動かしておくかは OctantCompass 自身が持ちます（ログインしたときに起動して常駐する設定など。[OctantCompass 法の 3](../octantcompass/law.md#3-起動と終了)）。常駐している間、OctantCompass は DB を読み込んだままにしなくてよく、DB を読み込んでいない間にトークン付きの要求を受けたら読み込みを始めて `loading` を返します。つなぐ側は今と同じく、`loading` の間は「準備中」と表示して `/v1/health` を待ちます（契約3（OctantPath ↔ OctantCompass）の状態のまま。形は変わらない）。DB を手放している間は、トークンのない `/v1/health` にも `loading` を返しますが、読み込みは始めません（同じネットワークの誰でも読み込ませられないようにするため）。

## 管理画面

OctantCompass の手元の管理画面（OctantCompass の窓）と管理 API（`/manage/`）は、契約3（OctantPath ↔ OctantCompass）にもこの契約にも含めず、[OctantCompass 法の 4](../octantcompass/law.md#4-管理画面)が持ちます。管理画面のページは窓が持ち、HTTP では配りません。そのため、ほかのアプリが URL で開くことはなく、URL の `lang`（2026-10-13）は使いません。

管理 API は、起動ごとの鍵を要ります（2026-10-23。それまでは鍵なし、2026-10-13 決定。鍵は OctantCompass の中の決まりで、この契約の外）。管理 API は同じ PC からの要求だけを受け、ブラウザのページからの要求は `Host` と `Origin` で断ります（[OctantCompass 法](../octantcompass/law.md#1-守る境界)の 1.10）。つなぐ側（OctantPath Desktop など）は管理画面を開かず、OctantCompass のファイルも読みません。ペアリングの合言葉は OctantCompass の窓に出ます
