# スイングシミュレーション

> 固さ: 後から記録する層（[憲法の原則 10](../constitution.md#10-段階と文書の固さ)）。モデルの説明で、値と特徴量の正本はコードです。

譜面を「プレイヤーがどう振るか」に変換し、その動きから難易度とプレイスタイル（ジャンル）を数値化します。ここがこのモデルの説明の唯一の場所です。数値パラメータとその既定値は `src/octantvector/generation/swing/params.py`、特徴量の一覧は `src/octantvector/generation/swing/features.py` の `NAMES`、スタイルタグの条件は `src/octantvector/generation/swing/style.py` の `FINE_TAGS` にだけあります。

## 参考にした公開手法

- **BeatLeader analyzer**（[BeatLeader/beatleader-analyzer](https://github.com/BeatLeader/beatleader-analyzer)、MIT、2026-02 時点の main）: BeatLeader の Pass / Tech レーティングの計算です。グリッドの実寸、パリティ中立角、角度ひずみ（angle strain）、再配置距離（repositioning）、回転量、スイングごとの難しさと窓平均による Pass、上位 75% の平均による Tech の式を Python に移植しました。Acc レーティングは学習済みモデル（非公開部分）なので含めていません。
- **JoshaParity**（[Joshabi/JoshaParity](https://github.com/Joshabi/JoshaParity)、MIT）: スイングの種類（stack / window / slider / chain）の分け方と、爆弾リセットを「前のスイングの後にセイバーが休む位置に爆弾があるか」で判定する考え方を参考にしました。
- **BeatLeader analyzer の壁補正**: 避ける壁・しゃがむ壁の間（前後 0.5 秒）のスイングの難しさを 1.1 倍・1.2 倍にする補正を取り入れました。壁の意味の分類と頭の動きのシミュレーションは独自です。
- **bs-parity**（[GalaxyMaster2/bs-parity](https://github.com/GalaxyMaster2/bs-parity)、GPL-3.0、BeatSaver が案内しているパリティチェッカー）: コードは使っていません。BeatSaver のパリティ集計の 3 つの数が何を数えているかを確かめるためだけに読みました（下の「教師データと評価」）。
- 帰属表示: [THIRD_PARTY_NOTICES.md](https://github.com/BeatOctant/OctantVector/blob/main/THIRD_PARTY_NOTICES.md)

## シミュレーションの流れ

`src/octantvector/generation/swing/` の中で、次の順に処理します。

1. **譜面の読み込み**（`chart.py`）: v2 / v3 / v4 形式を秒単位の時刻に直します。BPM 変化（v2 の `_events` type 100、v3 の `bpmEvents`）を反映します。v2 の `_BPMChanges` はエディタのグリッド用のデータでゲームは使わないため、無視します（使うと時刻が 2 倍速になる譜面がありました。exp16）。v4 は BPM 変化を別ファイルに持つため、Info.dat の BPM で計算します。Mapping Extensions の精密配置と角度、Noodle Extensions のノーツ・爆弾の配置（`coordinates`）も扱います。
2. **スイングへのまとめ**（`simulate.group`）: 同じ色で同時のノーツ（stack / window）、ごく短い間隔（または 1/8 拍以内）で向きの合うノーツ（slider）、チェーンを 1 回のスイングにまとめます。人が 2 回振れないほど近い同じ色のノーツは、向きにかかわらず 1 回にします。ドットを含む組は、さらに短い間隔（`dot_max_gap_s`）のときだけまとめます。上級者のリプレイでは、65 ms 以上離れたドットは必ず 2 回振っていました（exp18）。長く続く、または大きく曲がり続けるノーツの流れは、1 回ではなく複数のスイングに分けます。同じ手のスイングの間隔には下限を設け、速さと EBPM が現実離れした値にならないようにします。
3. **スイング方向**（`simulate.resolve_directions`）: 矢印はその角度（角度オフセット込み）です。ドットは流れの続き（前のスイングの逆方向）を基本に、配置の向きへ寄せます。
4. **フォアハンド／バックハンド**（`simulate.assign_parity`）: 手ごとに 2 状態の動的計画法（Viterbi）で、全体のコストが最小になる持ち方を選びます。コストは次の和で、間隔が長いほど小さくします。各項の重みは、上級者のリプレイに合わせて、同じ手のスイングの間隔が短いときと長いとき（`parity_long_gap_s` 以上）で別々に決めています（exp19）。
   - 手首のひねり: その持ち方の中立方向からのずれ（BeatLeader の中立角）
   - 回転: 予想される方向（持ち替えなら逆方向、リセットなら同じ方向）からのずれ
   - リセット: 持ち方を変えずにもう一度振るコスト。前のスイングの後にセイバーが休む位置に爆弾がある場合は安くなり（爆弾リセット）、逆に爆弾を突き抜けて持ち替えるコストが加わります。偽の爆弾と、爆弾で描いた絵（次の節のアート爆弾）はパリティに影響しません。
5. **壁と爆弾**（`hazards.py`）: 壁と爆弾を 1 つずつ、プレイヤーにとっての意味で分けます（次の節）。
6. **動きと難しさ**（`simulate.movement`, `swing_difficulty`, `ratings`）: 手首のロール角（中立からの符号付き角度）、入口／出口の手の位置、再配置距離、回転量、手の移動距離から、BeatLeader の式でスイングごとの難しさを出し、Pass と Tech にまとめます。避ける壁・しゃがむ壁の間のスイングには BeatLeader の壁補正をかけます。

計算は numpy と標準ライブラリだけで動き、GPU やモデルは要りません。

## 壁と爆弾

壁は頭にだけ当たり（セイバーは壁を通り抜けます）、爆弾はセイバーにだけ当たります。そこで壁は頭の位置、爆弾はセイバーの通り道と比べて、1 つずつ意味を決めます。位置はレーン（左端 0〜右端 4）と段（床 0、ノーツの 3 段が 0〜2）の単位です。

**壁**（`hazards.classify_walls`）

同じ大きさ・位置の壁がすき間なく続くもの（ごく短い壁を並べたトンネルなど）は、先に 1 枚の長い壁にまとめてから分けます（`hazards.join_walls`）。

| 種類 | 判定 | 意味 |
|---|---|---|
| アート（art） | Noodle Extensions の偽の壁（`fake` / 触れられない壁）、人が反応できない数が一度に出る壁（1 秒間の出現が多すぎる、同時に多すぎる。壁で描いた絵や演出）、ごく短い壁、大きさ 0 の壁、プレイ空間（グリッドの幅と高さ）の外の壁 | 障害物ではない演出・装飾 |
| 横の壁（side） | プレイ空間の中にあるが、中央に立った頭には届かない（外側レーンや低い壁） | プレイの枠や飾り。動く必要はない |
| 避ける（dodge） | 立った頭に届く | 横に動く・体を傾ける |
| しゃがむ（crouch） | 立った頭には届くが、しゃがんだ頭には届かない | しゃがむ |
| 避けられない（unavoidable） | 届く範囲の頭の位置をすべてふさぐ | 改造譜面の演出や偽の壁 |

運動量は頭の動きのシミュレーション（`hazards.head_path`）で測ります。一定の時間刻みで、壁にふさがれていない頭の位置のうち「中央に近く、前の位置から動かずに済む」ものを選び、横に動くより安ければしゃがみます。頭の移動距離（秒あたり）、中央から外れていた時間、しゃがんでいた時間、左右の切り替え回数が、壁による運動の量になります。実際のプレイヤーはしゃがむ壁の少し前からしゃがみ、少し後まで立ち上がらないので、その分（`head_crouch_margin_s`）を足します（exp18）。どれくらい動けるか、しゃがむ高さ、コストは `params.py` の `head_*` です。

**爆弾**（`hazards.classify_bombs`）

| 種類 | 判定 | 意味 |
|---|---|---|
| リセット（reset） | パリティの計算で爆弾リセットを起こした | 持ち方を変えずにもう一度振らせる |
| 回避（dodge） | 爆弾が来る前後に、どちらかのセイバーの通り道がすぐ近く（約 1 レーン以内）を通る | セイバーをよけて振る |
| アート（art） | 両方のセイバーの通り道から遠い。または偽の爆弾か、人が反応できない数が一度に出る爆弾（爆弾で描いた絵） | 演出・装飾 |
| その他（near） | どれでもない | 通り道の近くにある程度 |

セイバーの通り道は、各スイングの入口（少し前）と出口（少し後）を時間で結んだ線です。

**リズム**（`hazards.rhythm`）: 壁と爆弾の出現の時刻が 1/4 拍のグリッドに乗り、等間隔に 3 つ以上並ぶものをリズムに乗っているとみなします。ノーツと同じ時刻に出るものは「ノーツと同期」として別に数えます。リズムはプレイに関わる壁（避ける・しゃがむ）と爆弾（アート以外）で測ります。アートの壁が音楽に合わせて動く割合は別の特徴量にします。避ける・しゃがむ壁がリズムに乗って続く譜面は、音に合わせて体を動かす（踊る）壁です。プレイに関わる爆弾と同じ時刻に何個も並ぶ爆弾は、よけて通る爆弾の壁（クラスタ）として数えます。

ノーツが壁の中に入って見えにくくなる割合（視界をふさぐ壁）も数えます。

## 特徴量（`swing_flow`）

Standard の各譜面のシミュレーション結果を、譜面ごとに解釈できる特徴量に要約します。グループは、速さ（スイング数/秒、EBPM）、リズム（間隔の種類と変化、裏拍・3 連符、左右の交互、同時打ち）、手首（ロール角、逆手、角度ひずみ、斜め・横・非 45° 角）、パリティ（リセット率、ドット、直線的な流れ、回転量）、移動（再配置距離、ジャンプ、クロスオーバー、外側レーンと上下の段）、複数ノーツ（stack / window / slider / chain、アーク）、壁、爆弾（前の節の分類ごとの頻度と割合、頭の動き、リズム）、レーティング（Pass、Tech、短い窓と長い窓の Pass とその比、左右の偏り、NJS、NPS、長さ）、Acc 寄り（フルスイングできるスイングと中央寄りの配置の割合）です。特徴量の名前と並びは `features.py` の `NAMES` にあります。

プレイに関わる爆弾、または避ける・しゃがむ壁がごく少ない譜面（数は `params.py` の `hazard_min_count`）では、爆弾の特徴量と壁のリズムを 0 にします。ごく短い譜面（`hazard_min_length_s` 未満）では壁と爆弾の特徴量をすべて 0 にします。数個だけ、数秒だけでは譜面の傾向を表さないためです。

## スタイルタグ（`swing_style` / `swing_hazards`）

タグは 2 つのビューに分かれます。`swing_style` は学習タグと、壁・爆弾以外の細分タグです。`swing_hazards` は壁・爆弾の細分タグ（条件がすべて壁・爆弾の特徴量のタグ）だけです。壁や爆弾の好みは、ノーツの好みとは別の重みで推薦に使えるように分けています（exp12 で、1 つのビューにまとめると推薦の成績が下がりました）。どちらも `octantvector swing-train` が作るモデルファイル（設定 `swing_model`）を使います。タグは次の 2 種類です。

- **学習タグ（9 種）**: BeatSaver のスタイルタグ accuracy / balanced / challenge / dance-style / fitness / speed / tech と、poodle タグ、modded（Noodle Extensions・Mapping Extensions・Vivify が必要な譜面）です。マッパーが付けたタグとカタログの情報を教師にして、全特徴量のロジスティック回帰で確率を出します。タグの付いていないマップにも確率が付きます。自動生成・AI 生成と申告されたマップは学習に使いません。
- **細分タグ**: acc / tech などをさらに分けたタグで、特徴量に対する条件で決めます。条件は「プール内の分位（全難易度で計算）がいくつ以上／以下」または「値がいくつ以上／以下」です。全条件を満たすとタグが付きます。スコア（0〜1）は一番弱い条件の達成度で、タグが付かないマップの順位付けにも使えます。分位の条件ではタグ側の分位です。値の条件では、閾値に届かないうちは閾値に対する割合の半分（0〜0.5）、届いた後は 0.5 + 分位の半分（0.5〜1）なので、タグが付いたマップの間でも順位が付きます。分位は同じ値が並ぶ区間の中央を取るので、「爆弾リセットが 0」のような多数派の値が高いスコアになることはありません。設定ファイルの `[swing_tags]` で条件を変えたり、タグを追加したりできます（[config.md](config.md)）。

細分タグの系統は次のとおりです。条件は `style.py` の `FINE_TAGS` にあり、括弧の中は名前から分かりにくいタグの意味です。

- 速さ: `speed`、`stream`（左右交互の細かい連打）、`vibro`（同じ手のごく短い間隔の連打）、`burst`（短い区間だけ極端に難しい）、`stamina`（長く難しさが続く）、`midspeed`（中くらいの速さで、手首の負担が小さい）、`jumps`（短い時間で手が大きく移動する）
- テクニカル: `angle_tech`（中立から外れた角度のスイング）、`inverted`（手首を 90° 以上ひねる逆手）、`wrist_roll`、`rotation`（前のスイングの逆方向から外れた向きへの切り返し）、`bomb_resets`、`rhythm_tech`（間隔の種類が多く、頻繁に変わる）、`syncopation`（連打ではないのに 16 分の裏に入る）、`triplets`、`crossover`、`wide_reach`（外側レーンへの大きな腕の移動）、`dots`、`free_angles`（45° 刻み以外の角度）
- 流れ・精度: `flowy`（直線的で切り返しの少ない流れ。速い連打は除く）、`acc`（1 回ごとにフルスイングでき、角度と移動の負担が小さい）
- 配置: `windows`、`stacks`、`sliders`、`chains`、`arcs`、`doubles`（左右同時打ち）
- 壁（`swing_hazards`）: `art_walls`（障害物ではない演出の壁）、`workout_walls`（壁をよけるための頭の移動が多い）、`dodge_walls`、`crouch_walls`、`rhythm_walls`、`dance_walls`（避ける・しゃがむ壁がリズムに乗って続く。音に合わせて体を動かす）、`vision_walls`（ノーツが壁の中に入って見えにくい）
- 爆弾（`swing_hazards`）: `bombs`、`art_bombs`（セイバーから遠い演出の爆弾）、`dodge_bombs`（セイバーの通り道の近くでよける必要がある）、`rhythm_bombs`、`bomb_walls`（プレイに関わる爆弾がまとまって壁を作り、その間を通して振る）
- 体・視認: `one_hand`（片手に偏っている）、`high_njs`
- 譜面の作り: `parity_breaks`（爆弾なしで同じ持ち方のまま続けて打つ。BeatSaver のパリティ集計の errors とよく一致する。exp11）、`unsnapped`（1/8・1/6 拍のグリッドから外れたタイミングが多い）、`dense_low_njs`（密度が高いのに NJS が低い）

## 教師データと評価

`octantvector swing-dataset` は、プールの全マップの全 Standard 難易度について、特徴量とカタログにあるラベルを 1 行ずつ書き出します。ラベルは、マッパーが付けたスタイルタグ（accuracy / balanced / challenge / dance-style / fitness / speed / tech）、ランク譜面の ScoreSaber と BeatLeader の星、BeatSaver 自身のパリティ集計です。公開マップから作ったデータで、個人データは含みません。

`octantvector swing-train` はこのファイルからスタイルモデルを作り、`octantvector swing-eval` は次を報告します。交差検証はマッパー単位で分けるので、同じマッパーの作風で答えが漏れることはありません。

- 難易度: Pass / Tech / NPS と星の順位相関。全特徴量のリッジ回帰（交差検証）と、NPS・NJS だけの回帰との比較
- 難易度の並び: 同じマップで難易度が上がると Pass も上がる割合（NPS と比較）
- 学習タグ: タグごとに、全特徴量のロジスティック回帰（交差検証）の AUC。NPS・NJS だけのモデルと比較
- 細分タグ: 付いたマップの割合、各 BeatSaver タグが付く割合の何倍か（リフト）、マップの説明文と難易度ラベルの単語（tech、vibro、bomb resets など）に対するスコアの AUC。単語は評価にだけ使い、特徴量にはしません。「no resets」のような否定も拾うので、この AUC は下限です
- 単語と特徴量: 単語ごとに、その単語を含むマップを一番よく見分ける特徴量（AUC、上位 5 つ）。細分タグの条件を見直す手がかりです
- パリティ: シミュレーションのリセット数（爆弾リセットとそれ以外）と、BeatSaver のパリティ集計の 3 つの数の順位相関。BeatSaver が案内している bs-parity では、爆弾で持ち方が変わった回数が resets、爆弾なしで同じ持ち方のまま打つ回数が errors（境目の角度は warns）です。BeatSaver の集計も同じ数え方だと考えられるので、爆弾リセットは resets と、それ以外のリセットは errors と比べます

`swing_style` の学習タグは全マップで学習したモデルの出力なので、そのビューで近傍評価をすると学習タグの分だけ少し楽観的になります。

シミュレーション自体は、上級者の公開リプレイ（BeatLeader の .bsor。手と頭の位置・向きがフレームごとに入っています）と比べて確かめました（exp18）。リプレイは個人のプレイデータなので、リポジトリには入れません。

結果と結論は [experiments.md](experiments.md) に記録します。

## 既知の限界

- アーク（arc）はスイングの形に反映していません（数だけ数えます）。
- 壁と爆弾の判定は Standard の 3×4 グリッドと立った位置が基準です。Noodle Extensions のアニメーションで動く壁・爆弾や、壁の奥行き方向の位置は見ていません（Noodle の静的な配置 `coordinates` はノーツと爆弾に使います）。
- 爆弾をよけるためにスイングの形が変わることは、パリティ（リセット）以外には反映していません。
- 360 / 90 度譜面と、v4 の BPM 変化には対応していません。
- 「譜面の作り」の系統のタグ（`parity_breaks`・`unsnapped`・`dense_low_njs`）は、どの BeatSaver スタイルタグとも結び付きません（exp10）。プレイスタイルではなく譜面の作り方を表すタグとして扱います。
- `triplets` もどの BeatSaver スタイルタグとも結び付きません。リズムの特徴として残しています。`flowy` と `vision_walls` は、説明文の単語（flow、vision block）とはほぼ一致しません。`flowy` は accuracy タグとは結び付きます（リフト 2.6）。いずれも exp17 です。
- 同じ色のノーツが数ミリ秒おきに並ぶ演出用の譜面（VISUAL・ミーム譜面など）は、Pass が実際より高く出ることがあります。ランク譜面では Pass が星の 2 倍を超えるものはほぼありません（exp17）。
- 上級者のリプレイと比べると、細かい角度の矢印（35°、225° など）が続くところでシミュレーションはリセットし、プレイヤーは手首を返して流すことがあります（exp19 で一部改善）。長い間の後のドットをリセットする譜面もありますが、2 譜面に偏った癖で、一般的な規則にすると全体の一致が下がりました（exp19）。
- 壁・爆弾のタグ（`swing_hazards`）を推薦に加えると、個人評価は良くなりませんでした（exp13〜exp17）。推薦には `swing_style` を使い、壁・爆弾は絞り込みや別の軸として使う想定です。
