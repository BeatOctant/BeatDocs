# OctantPath 実装構想

2026-10-01 作成 · 状態: 実装済み（OctantPath の MOD と OctantPath Desktop。部品の名前と分け方はコードにある）

## 前提と目標

OctantPath はゲーム内の MOD で、推薦はゲーム外の OctantCompass から契約3（OctantPath ↔ OctantCompass）で受け取ります。最初は Beat Saber の PC 版（Steam）の 1 つの版だけに対応します（今の版は OctantPath の README の「組み合わせる版」）。ゲーム本体への独自パッチは避け、MOD 界隈で定番の公開ライブラリと、ゲームが Zenject で公開している部品の範囲で組み立てます。

- 目標: ゲーム内で推薦を受け取り、専用プレイリストへ自動ダウンロードし、残すか消すかを自動で決める
- MOD、OctantCompass、OctantVector の間の取り決めは [契約](../contracts/README.md) にあり、この文書では繰り返しません。変えてほしい点は contracts/ の方を直します。実装が守る意味は [OctantPath 法](../octantpath/law.md)にあり、食い違えば法が優先です
- MOD と OctantCompass は契約3 の API と契約6（つなぐ側 ↔ OctantCompass）の接続の手順だけでつながり、OctantPath の実装は OctantCompass の中身に依存しません（憲法の原則 8）。ゲームのフォルダ（曲ファイルとプレイリスト）に触れるのは MOD だけです

## 使うライブラリ

MOD は、PC 版の MOD の多くが前提にしている定番ライブラリだけに依存させます。版は MOD の `manifest.json` の `dependsOn` にあります。

| ライブラリ | 必須か | OctantPath での用途 |
| --- | --- | --- |
| BSIPA | 必須 | MOD の読み込み、設定ファイル（`UserData` 配下）、メインスレッドへの戻し（`IPA.Utilities.Async`） |
| SiraUtil | 必須 | Zenject への部品の登録。ゲームの `PlayerDataModel` や結果画面の部品を注入で受け取り、パッチを書かずに済ませる |
| BSML（BeatSaberMarkupLanguage） | 必須 | 画面 |
| SongCore | 必須 | カスタム曲の読み込みと再読み込み。`Collections.AddSeparateSongFolder` で OctantPath 専用の曲フォルダを独立したパックとして登録する。削除、再読み込み、読み込みの完了も公開 API で、パッチは要らない（開発の 1.40.8 の環境の SongCore 3.15.3 を逆コンパイルして確認） |
| BeatSaverSharp | 使わない | BeatSaver API は `HttpClient` で直に呼ぶ（OctantPath #28 で外した） |
| BeatSaberPlaylistsLib | 必須 | 専用プレイリスト（`.bplist`）の作成と更新 |
| PlaylistManager | 推奨 | プレイリストを曲選択画面に出す。入っていなくても専用パックで遊べる |
| BeatSaverVoting | 任意 | Upvote / Downvote の入口。他の MOD 向けの公開 API はないので、投票記録ファイルを読む（形式は [契約の外部依存](../contracts/external.md)） |
| SongPlayHistory / DataRecorder | 任意 | OctantPath を入れる前の 1 プレイごとの記録。取り込み元は 2026-10-03 決定（[過学習の設計](personal-data-overfitting.md#過去のプレイ記録の取り込み元)）。取り込みは未実装 |

## MOD の中身

MOD は「表示する、観測する、曲ファイルを出し入れする」の 3 つだけを担当し、推薦の計算は OctantCompass に任せます。シグナルはこの環境の正本として `UserData/OctantPath/` に残し、OctantCompass の起動（`/v1/health` の `instanceId`）が変わったら丸ごと送り直し、あとは足した分だけ送ります（契約3 2.0）。HTTP はすべて非同期で呼び、画面を書き換えるときだけメインスレッドに戻します。ゲームプレイ中は通信もファイル操作もしません。MOD が書くファイルは [OctantPath の README](https://github.com/BeatOctant/OctantPath/blob/main/README.md#mod-が書くファイル)にあります。

## シグナルとマップの入れ替え

OctantPath が入れたマップは全部「お試し中」から始まり、はっきりした好意が出たら「残す」、出ないまま期限を過ぎたら消します。

### 集めるシグナル

| シグナル | どこから取るか | 「残す」の判定 |
| --- | --- | --- |
| Upvote / Downvote | BeatSaverVoting の投票記録。結果画面を閉じたあとに差分を見る | Upvote で残す。Downvote で消す |
| いいね | ゲームのお気に入り（`PlayerDataModel`）。メニューに戻ったときに差分を見る | 残す |
| クリア・失敗（ミスによる failed） | 結果のイベント | プレイ回数に数え、設定の「残す」のプレイ回数以上で残す |
| 途中終了・やり直し | 結果のイベント | プレイ回数に数えない |
| ユーザーによる削除 | 台帳にあるのに MOD が消していないマップが消えていた | 台帳で削除済みにする |

シグナルはどれも契約3 で OctantCompass に送り、好みと実力への使い方は契約1（OctantCompass・OctantHarvest → OctantVector）に従います。失敗もプレイ回数に数えるのは、クリアできなくても楽しいマップがあるためです。途中終了とやり直しは好みかどうか分からないので数えません（2026-10-01、2026-10-06 決定）。

### 曲ファイルの置き場（専用フォルダ）

「専用フォルダ」は、OctantPath が取得した「お試し中」のマップだけを置く曲フォルダです（SongCore の `AddSeparateSongFolder` で独立したパックにする）。そのマップがゲームの中で `CustomLevels` のマップと同じように遊べるか、プレイリストや投票、お気に入りが普通に動くか、ほかの MOD が嫌がらないかは、ゲームの中で確かめることです（[open.md の OctantPath](../open.md#octantpath)）。使えなかったときは `CustomLevels` に入れ、「お試し中」かどうかは台帳だけで見分けます。そのときは、台帳が壊れたら自動削除を止める決まり（「既存のマップとの区別」）が唯一の歯止めになります。シンボリックリンクで `CustomLevels` から指す案は勧めません（推測で、試していない。Windows では管理者権限か開発者モードが要り、二重に読まれたりリンク経由で本体まで消したりするおそれがある）。

### マップの入れ替え

1. 「似ている」の意味ごとの枠（下の表）で推薦を受け取り、枠ごとに上位からお試し枠が埋まるまでダウンロードし、台帳に「お試し中」として記録する
2. 曲ファイルは専用フォルダに置き、`CustomLevels` とは分ける。消してよいマップがフォルダ単位ではっきりする
3. Upvote、いいね、「残す」のプレイ回数以上のどれかで「残す」にする。残すマップは `CustomLevels` へ移し、以後は既存のマップと同じ扱いにする
4. 「お試し中」のまま期限を過ぎたものと、Downvote したものを、メニューにいるときに消す。他のプレイリストに入っているマップは消さない
5. 消したマップは次の推薦要求で除外に入れ、同じマップが戻ってこないようにする

1 の取得は、推薦を受けるたびに枠が埋まるまで、遊ぶかどうか分からないマップを先に取ります。遊ばなかったものは 4 で消すので、BeatSaver から見ると取っては捨てる量が多くなります。そのため、**既定ではどの枠も 0 件で、自動の入れ替えは何も取りません**（2026-10-11）。ユーザーが枠の件数を設定したときだけ動きます。ふだんの取得は、ミックスで試聴して選んだ曲だけです（「ミックスの今の形」）。試験のあいだは zip の取得元をローカルのフォルダにし、BeatSaver からは取りません（2026-10-08 決定）。

#### 取得を減らす案

[open.md の OctantPath](../open.md#octantpath) の U3 へ移しました。

### 「似ている」の分け方

お試し枠は「何が似ているか」ごとに分け、枠ごとに専用プレイリストを持ちます。曲ファイルの置き場は専用フォルダ 1 つのままです。

| 枠 | 名指しする手札 | 似ているもの |
| --- | --- | --- |
| 曲が似ている（`song`） | `song`（似た曲。楽曲ベクトル CLAP・MERT と近いアーティスト） | 曲調、雰囲気、アーティスト |
| ジャンルが近い（`genre`） | `genre` に `choices.genre` で語を付ける（[推薦の定義](recommendation-definition.md)の Q2 のジャンルの言葉の入り口）。語を決めるまで使わない | ジャンル |
| 譜面が似ている（`chart`） | `chart`（似たマップ。譜面ベクトル `chart_patterns`） | マッパーの癖、配置、密度 |
| 難易度が合う（`difficulty`） | `for_you`（おすすめ。履歴から、実力に合わせて） | 今の実力で遊べる譜面 |

- 枠ごとに推薦要求を分け、手札の id と入力で切り替える。枠は画面の分け方で、契約には出てこない（[推薦の定義](recommendation-definition.md)の Q1）。枠がどの手札を名指しするかは設定（`trialFrames`）にあり、OctantCompass の手札の一覧（`/v1/presets`）を受け取ってから、その中にある手札の枠だけを埋める。一覧にない手札の枠は空のまま（OctantPath #30。[プリセットの 12 節](presets.md#12-手札はビューを名指しする2026-10-14)）
- 手札の中の条件（重み、狙い）は OctantVector の手札が持ち、OctantPath は持たない。OctantPath は要求に重みを送らないので、応答の `ignoredWeights` は使わない（DB にないビューを名指しする手札は一覧から外れ、その枠は空のまま）
- 枠の件数は設定で変えられ、使わない枠は 0 にできる
- 台帳にはどの枠で入ったかを記録する。「残す」になった割合を枠ごとに見れば、どの意味の「似ている」が好みに合うか分かる
- 同じマップが複数の枠に出たら、そのすべてのプレイリストに入れる。曲ファイルは 1 つだけで、台帳には入った枠をすべて記録し、枠ごとの「残す」の割合ではそれぞれの枠に数える。お試し枠の件数も枠ごとに数える

### 既存のマップとの区別

手元のマップは 3 種類に分け、OctantPath が消す可能性があるのは「お試し中」だけです。判定は「専用フォルダにある」かつ「台帳にある」の両方で行い、どちらかが欠けたら既存扱いにします。

| 種類 | 判定 | 推薦 | 自動削除 | シグナル |
| --- | --- | --- | --- | --- |
| 既存（OctantPath 導入前からある、または自分で入れた） | 専用フォルダの外にある | 入る。取り直さずに表示する | しない | 好みと実力に使う |
| お試し中 | 専用フォルダにあり、台帳で「お試し中」 | — | 条件を満たさなければする | 使う |
| 残す | `CustomLevels` へ移した時点で既存と同じ（台帳には履歴として残る） | 入る。取り直さずに表示する | しない | 使う |

- 入っているマップも推薦に入る（[契約3（OctantPath ↔ OctantCompass）](../contracts/mod-api.md)。2026-10-09 に、入っているマップをすべて除外する決まりをやめた）。入っているマップは取り直さない。どの場面で出さないか（例: お試し枠の自動ダウンロードでは入っているものを除く）は場面ごとに決める
- 既存のマップがお試しに入ることはない。お試しになるのは OctantPath が取って置いたものだけ（[OctantPath 法](../octantpath/law.md) 3.1）
- お試し中のマップと同じ `hash` を自分で別の場所に入れたら、既存扱いに切り替え、専用フォルダの重複分だけを消す
- 台帳が壊れたり消えたりしたときは、専用フォルダの中身も自動削除しない（安全側に倒す）

### 設定

設定は `Beat Saber/UserData/OctantPath/` の JSON ファイル（`settings.json`）に置きます（2026-10-01 決定）。推薦の数値（契約1 の `params`）もこのファイルが正本で、推薦の要求に付けて OctantCompass に送ります（契約3。2026-10-06 決定）。既定値の正本は OctantPath に埋め込んだ [`src/OctantPath.Core/Settings/defaults.json`](https://github.com/BeatOctant/OctantPath/blob/main/src/OctantPath.Core/Settings/defaults.json) で（OctantPath #29、2026-10-14）、`settings.json` には変えた項目だけが残ります。項目の意味は [OctantPath の README の「設定」](https://github.com/BeatOctant/OctantPath/blob/main/README.md#設定)にあります。

## 画面

見せ方は未決です（[open.md の U4](../open.md#octantpath)）。画面は BSML で作り、遊ぶときは普段の曲選択画面から専用パック（または専用プレイリスト）を開きます。今の形は次のとおりです（憲法の原則 10 の後から記録する層。OctantPath の `docs/mix-flow.md` の 4 節に作りの記録）。

### ミックスの今の形（2026-10-10、実装に合わせて記録）

1. 曲選択の上の浮かぶ板は「手札の板」にする。推薦のカード（「ミックス」と、起点の要らない手札）と「保存」「移動」だけを置き、中央の画面と同じ一覧は出さない。将来は手札がここに並ぶ（決定）
2. 「ミックス」（板か、曲の詳細のアルバムアートの左上の ♪）を押すと、中央の画面に種類の小窓が出る。手札の `group` があれば見出しで分ける
3. 種類を選ぶと下見の小窓に変わる。並んだ曲は取得しない（試聴だけ）。1 曲目の試聴を自動で流し、取り終えたら並んだ曲の試聴を上から 1 曲ずつ先読みする。各行の ✕ で外し（入れ替えない）、⇔ で入れ替え、↓ でその 1 曲だけ取得する。取得が済んだ曲は ↓ が ▶ になり、押すと曲選択でその曲を選ぶ（PLAY はユーザー）。その曲を遊んで曲選択に戻ると下見の小窓を開き直す。一覧の一番下の「曲を足す」で 1 曲ずつ足せる（20 曲まで。2026-10-22、OctantPath #52）。入れ替え用が少なくなったら、同じ条件で、これまで出した曲を除いて追加を受け取る（頼む数と補充の決まりは OctantPath.Core の `MixDraftRules`）
4. 「作成」で並んでいる曲だけを取得し、一時的なプレイリスト（作るたびに置き換わる。OctantPath の印付きなので自動削除から守らない）を曲選択で開く。取得の量を、ユーザーが選んだ曲だけに絞るため（全ユーザーが 14 万マップを取ることになりかねない）
5. 遊び終えると、結果画面の上に、遊んだ譜面を起点にしたおすすめを数曲出す。行を押すとその曲の試聴だけを流し、行の ▶ でその曲を次の曲にする（押しただけで曲選択へ移ると、聞いてから決められなかった。2026-10-24、OctantPath #65）
6. OctantCompass につながらないとき、推薦の要求が失敗したときは、中央に数秒の知らせを出す。推薦が 0 件のときは「推薦がありませんでした」に理由を添える

- 下見の ↓ で取ったマップは、台帳の枠を「手動」（ユーザーが選んだ曲）にする。自動削除の扱いはお試しと同じ
- 下見で外した曲は、`recommendation` の signal を段階 `skipped` で送る（`shown`、`selected` と同じく契約3（OctantPath ↔ OctantCompass）の自由な段階の文字列）
- BeatSaver に推薦された hash の版がない曲（削除されたマップ、古い版。試聴もカバーも取得もできない）は、下見にも、5 の結果画面のおすすめにも出さない。MOD と Desktop で同じ決まりにする（2026-10-11）。並び順は変えない
- 曲を始めるのはゲームの PLAY のまま（推薦の画面から直接始めない。ゲーム内部に依存しやすいため）
- 推薦の理由のビューは、中の名前（`id@version`）ではなく役割の名前（「曲の音」「譜面」「タグ」「アーティスト」「歌声」）で出し、中の名前は指を置いたときに見せる。ビューの役割は `/v1/health` の `db.roles` から引く（契約の形は変えない）。同じ役割のビューが 2 つ以上あれば id の最初の語を添えて分け（「曲の音 · CLAP」「曲の音 · MERT」）、役割の分からないビューは id から版を外して出す（2026-10-13。今は Desktop だけが理由のビューを出す。OctantPath #25）

## 未決事項とリスク

### まだ決まっていないこと

OctantPath の実装が守る意味のうち決まっていないものは、[OctantPath 法の「未決」](../open.md#octantpath)にだけ書きます。

### 実装前に確かめること

[open.md の OctantPath](../open.md#octantpath)（G5、U1）と、[decisions.md の OctantPath](../decisions.md#octantpath)（U2。2026-10-08 の行）へ移しました。

### リスク

- ゲームの更新で Zenject の部品名が変わると、シグナルの観測が壊れる。そこだけを小さな部品に閉じ込め、壊れても推薦とダウンロードは動くようにする
- 自動削除の不具合で元からあるマップを消すと取り返せない。対策は「既存のマップとの区別」の判定と、設定の削除の試し運転（確かめてから切る）
