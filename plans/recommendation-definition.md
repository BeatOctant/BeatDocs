## この文書の役割

OctantVector が何を推薦し、何を返すのかを先に決め、そのために何が要るかを導いてから、OctantPath・OctantCompass・OctantVector の契約を書き直します。今までは推薦そのものの定義がないまま契約を書いたため、契約1（OctantCompass・OctantHarvest → OctantVector）・契約3（OctantPath ↔ OctantCompass）と構想の文書が別々に推薦の形を決め、手戻りが何度も起きました（2026-10-04）。

- 契約の文面は contracts/ の契約1（OctantCompass・OctantHarvest → OctantVector）・契約3（OctantPath ↔ OctantCompass）にあり、この文書は決定とその理由だけを持ちます
- 各 Q には決めたことと理由だけを書きます。検討した選択肢は OctantSpecs #28 の履歴にあります

## 1. 決まっていること

| 事柄 | 中身 | 出所 |
| --- | --- | --- |
| 推薦の対象 | 推薦の各項目は 1 つの Chart を指す。内部で Map 単位に探してよく、1 Map あたりの数を絞ってよい | 憲法の原則 1 |
| Chart の識別 | BeatSaver の version hash + `characteristic` + `difficulty`。map key は表示だけ | 2026-10-01 |
| 旧版 | 旧版を指す入力は同じ Map の現行版に置き換え、置き換えたことを返す | 2026-10-02（決定 B） |
| 粒度 | play は Chart 単位、お気に入りと投票は Map 単位で観測し、その粒度のまま持つ。プレイスタイルの違う Chart どうしは比べない | 憲法の原則 2 |
| 役割 | 評価の計算は OctantVector だけ。OctantCompass は条件をまとめて OctantVector を呼び、再評価しない。OctantPath は推薦の順位を変えない | 憲法の原則 3〜6 |
| 好意 | クリアしたマップのお気に入りか Upvote（どちらか一方でよい）、またはクリアした後に別の日にまた遊んだ。未クリアの繰り返しは好意にしない。未クリアのマップのお気に入りか Upvote は「目標」として挑戦の推薦に使う。曖昧なシグナルは負例にしない | 2026-10-01、2026-10-10 に変更（[OctantVector 法](../octantvector/law.md) 4.1） |
| 難しさ | 1 本の数値ではなく、その人の得意な Chart からの特徴空間での距離 | 2026-10-03 |
| 似ている度合い | ビューごとの結果が基本で、重み付きの結合はその上。片方に欠けたビューは 0 点で、重みを割り直さない | 2026-10-02（決定 E）、2026-10-03 |
| 曲名 | 特徴に使わない | 2026-10-01 |

## 2. 決めたこと

2026-10-04 に決めました。

### Q1. 推薦は 1 種類で、種類の違いは条件で表す

OctantVector の推薦は「この人に、いま遊ぶ Chart を順位付きで返す」1 種類だけです。画面での推薦の種類（好みだけ、この Chart から、ジャンルの言葉から など）は、条件の組み合わせ（起点、難易度の絞り込み、ジャンルの言葉の絞り込み、似ている軸の重み）で表します。種類を足しても契約は変わりません。

### Q2. 推薦の入り口は 3 つ

| 入り口 | 条件 | 例 |
| --- | --- | --- |
| 好みだけ | 起点なし。難易度で絞り込む | 「おすすめ」 |
| Chart から | 起点は 1 つの Chart（Map の中で選べる 1 つの譜面）。譜面の軸は同じプレイスタイルの Chart だけと比べる | 表示中の譜面を選んで推薦ボタンを押す |
| ジャンルの言葉から | 決めた語（最大 10 語程度）の中から選び、音声の特徴がその語に近い Map に絞り込む。その中を「好意のラベルが付いた最近プレイした Map」の音楽の特徴に近い順に並べる。難易度でも絞り込む | 「J-POP」を選ぶ |

- ジャンルの言葉は BeatSaver のタグではなく、音声の特徴で引きます（理由: BeatSaver のタグは機械的に使うには信用しにくい。根拠は印象で、検証はしていない）。語の一覧は固定なので、語ごとの近さを配布 DB に入れて配れます。利用者の PC で音声とテキストのモデルを動かす必要はありません
- その後、語は BeatSaver のタグから取り、タグのない曲は音で当たる語だけ音（`clap_concepts`）で補うと決めました（2026-10-09。Spike R1 で、音で決まるジャンルは当たるが、pop、j-pop、anime、vocaloid などは出現率以下だった。[decisions.md の推薦の定義](../decisions.md#推薦の定義)）
- 「最近プレイした Map のうち、好意のラベルが付いているもの」を基準にします。好意のラベルがいつ付いたかは問いません。「最近好意的になったもの」だけだと新しい発見が少なく、「直近のプレイ」全部だと推薦されて試したが好きではなかった Map まで基準に入るためです
- Map を起点にする入り口は、今は作りません
- 語の一覧そのもの、「最近」の範囲は未決です（[open.md](../open.md#推薦の定義)）

### Q3. 返すものは Chart、順位、理由

| 項目 | 意味 | 使い道 |
| --- | --- | --- |
| Chart（hash、`characteristic`、`difficulty`） | 推薦する Chart | 取得と再生 |
| 順位 | OctantVector が付けた順位。OctantPath と OctantCompass は変えない | 「Recommended 順」の表示 |
| 理由 | 似ている軸ごとの寄与、難しさ（Q4 の尺度での位置）、一番近い得意な Chart | 表示だけ。並べ替えや絞り込みに使わない（憲法の原則 6） |
| 置き換え | 旧版の入力を現行版に置き換えたか | 表示とログ |

- `score` は返しません。同じ応答の中でしか比べられない値で、別の応答と混ぜて並べ直す余地を作るためです
- 1 Map から返す Chart は既定で 1 つで、条件で増やせます
- 同じ曲を別のマッパーが作った Map も、既定で 1 つだけ返します。音声がほぼ同じなので、有名な曲を起点や好意にすると、同じ曲の Map が一覧を埋めていました（2026-10-08）。同じ曲かの見分け方と数は OctantVector の中の決めごとです（[OctantVector 法](../octantvector/law.md) 3.4）
- 件数に足りないときは足りないまま返します

### Q4. 狙いを選ぶのは OctantCompass、尺度は OctantVector

狙い（ふつう・挑戦・慣らし、セッションの前半・後半で変えるなど）を選ぶのはスケジューリングなので、OctantCompass がします（解釈）。OctantCompass は特徴の空間での距離を計算せず、OctantVector が決めた標準の尺度の上の値で狙いを渡します。尺度は「その人がその Chart をクリアできる見込み」を案とし、ふつう・挑戦・慣らしの既定値も OctantVector の尺度に合わせて決めます。尺度を OctantVector が決めるので、特徴や距離の計算方法を変えても OctantCompass は変わりません（憲法の原則 4）。

### Q5. 好みと実力は契約に出さない（暫定）

OctantCompass は推薦のたびに、保存している履歴（signal と play、受け取ったままの粒度）を OctantVector に渡します。好みと実力は OctantVector の中で作り、作り直しを避けるキャッシュも OctantVector の中に置きます。OctantCompass は好みと実力の中身も、作り直す時期も扱いません。

- OctantCompass は OctantVector を同じプロセスの中で呼ぶので、履歴を渡すのに通信はありません。残る費用は好みと実力を作る計算時間で、OctantVector の中のキャッシュで避けられる見込みです（推測で、まだ測っていない）
- **確定の条件**: OctantVector の推薦側を作るときに、開発に使った履歴の量で 1 回の推薦にかかる時間を測る。遅ければ、好みと実力を OctantCompass が受け取って保管する形（以前の契約の形）を見直す

### Q6. `search` は契約から外す

OctantCompass は件数と条件を渡して推薦を頼み、OctantVector ができあがった推薦の一覧を返します。ビューごとの Top-k は OctantVector の中と開発補助ツールで使います。

### Q7. 出さないものは、OctantPath が伝えられる範囲で任意に渡す

- 導入済みの Chart も推薦に入れてよい。OctantPath は導入済みのものを「DL 済み」として表示する
- 出さないもの（Map 単位か Chart 単位）は、推薦の条件として任意で渡せる。お試し枠の自動ダウンロードのように、場面によって OctantPath が使い分ける
- 理由の種類や必須の項目は今は固めない。OctantPath で何が分かるか（取得失敗、利用不能など）は実装してみないと分からず、固く作ると後で困るため。契約は「任意の除外と、任意の理由の文字列」にとどめ、OctantVector は知らない理由を除外としてだけ扱う

### Q8. 推薦のその後の出来事は送って記録し、好みにはまだ使わない

- OctantPath は、推薦した Chart について観測できた出来事（表示した、ダウンロードした、選んだ、プレイした など）を `requestId` と一緒に OctantCompass に送り、OctantCompass が記録する（履歴の正本は OctantPath で、OctantCompass は記録をキャッシュし、session context はそこから作る。憲法の原則 5・7。2026-10-12 に憲法に合わせて直した）
- 好みには使わない（曖昧なシグナルは負例にしない）。遊ばれなかったのが体力のせいか、嫌いだったからかは区別できず、ユーザー体験としてどう受け取られるかもまだ分からないため
- 使い方は、記録がたまってから決める。推薦のその後を考えたときも、そのままにした（2026-10-10、[decisions.md の推薦のその後](../decisions.md#推薦のその後)）

## 速さが要る通信

ユーザーを待たせる順に並べます（2026-10-04）。OctantCompass と OctantVector の間は同じプロセスの中なので、通信はありません（Q5）。

| 順 | 経路 | 待たせる場面 | 今の考え |
| --- | --- | --- | --- |
| 1 | BeatSaver → OctantPath（Map の取得） | 推薦を選んでから遊べるまで | 一番効く。導入済みの Chart は取り直さない（Q7） |
| 2 | 推薦を始めるまでのデータ集め（OctantPath の観測、導入前の記録の取り込み） | 最初の推薦が出るまで | 観測したときに 1 件ずつ送り、推薦のたびに集め直さない。導入前の記録は一度だけ取り込む（今は OctantPath が初回に取り込む。履歴の正本は OctantPath で、憲法の原則 5・7） |
| 3 | OctantCompass → OctantPath（推薦の結果） | 推薦ボタンを押してから一覧が出るまで | 件数分の Chart と表示に要る理由だけを返す |
| — | 配布先 → OctantCompass（DB） | 待たせない | 古くても困ることは少ない。裏で差分を取る（契約5（OctantHarvest → 配布先 → OctantCompass）） |

どれも時間はまだ測っていません。

**将来の Map の先読み（今は作らない）**: Map の取得が遅ければ、推薦に出そうな Map を前もってローカルに置き、OctantPath の取得先をそこに向けて速くする部品（例: BeatCache）が要るかもしれません（2026-10-04）。Map をゲームに取得して導入するのは、そのあとも OctantPath の責務です（憲法の原則 5）。変わるのは OctantPath の取得先だけで、BeatSaver の代わりにローカルの置き場から取れるようになります。作るときに決めることは、置き場の持ち主（OctantCompass か別の部品か）と、何を前もって置くかを推薦から知る方法です。部品を足すのは憲法の構成を変えることになるので、メンテナーが決めます。今の契約では、OctantPath の取得先を設定で変えられるようにしておくことと、推薦の要求を表示の直前に限らず前もって出せるようにしておくことだけを守ります。
